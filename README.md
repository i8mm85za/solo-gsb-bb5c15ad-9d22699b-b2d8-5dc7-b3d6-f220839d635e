# 法规条款变更审阅 Web 应用

上传法规/制度文本的**旧版**与**新版**，系统按**段落顺序 + 字符串相似度**自动生成可解释的
条款对齐候选，识别 **未变更 / 改写 / 新增 / 删除 / 拆分 / 合并 / 多段改写** 并给出置信度；
审阅者可手动调整映射、记录审阅决定与备注、按变更类型/状态/关键字筛选，并导出包含
**两版原文、变更类型、判定依据、审阅决定**的结果文件（CSV / Markdown / JSON）。

此外提供 **引用检查** 模块：在文档详情中扫描**新版条款**里“第十条”“第十条第二款”
“本条前款”“前两款”等引用，解析中文/阿拉伯数字与相对指代，按新版 条/款/项 段落结构
定位**唯一目标**；找不到目标标为 **缺失**，存在多个候选标为 **歧义**（保留全部候选，
**绝不静默选取**）。支持按检查状态筛选、从问题项跳转对照“来源原文 ↔ 目标/候选原文”，
并可导出**引用问题 CSV**。

技术栈：**Python 3.11 · FastAPI · SQLite（标准库 sqlite3，无 ORM）· 原生 JavaScript/CSS**，
无前端构建步骤，无外部 NLP 依赖。

## 使用流程

1. **新建审阅**：填写名称，分别粘贴旧版/新版纯文本（段落之间建议空行分隔；
   `第一条`、`1.`、`（一）` 等编号行会被自动识别为段落边界），点击「生成对齐候选」。
   也可点击「填入示例文本」快速体验。
2. **复核候选**：每张卡片展示
   - 变更类型徽标、**置信度**进度条与段落相似度；
   - **判定依据**（中文可解释说明，含相似度数值）；
   - 旧版/新版原文对照，字符级差异红/绿高亮；
   - 是否为「人工调整」。
3. **记录决定**：选择 **待审阅 / 确认 / 有异议 / 忽略**，填写审阅备注。
4. **调整映射**：
   - 卡片上「✎ 调整映射」可勾选旧/新段落重新建立对应（多旧→一新＝合并，
     一旧→多新＝拆分，也可强制指定变更类型）；
   - 「删除映射」释放段落，工作区顶部「＋ 新建映射」可重新关联未映射段落；
   - 同一段落不允许同时出现在两条映射中（接口返回 409）。
5. **筛选**：顶部统计胶囊按变更类型筛选；下拉按审阅状态筛选；搜索框匹配原文/依据/备注。
6. **重新对齐**：放弃全部人工结果，按当前文本重新计算。
7. **导出**：「⬇ 导出」按当前筛选条件导出
   - **CSV**（UTF-8 BOM，Excel 可直接打开）
   - **Markdown 报告**（人类可读，含每条两版原文引文）
   - **JSON**（结构化全量数据，便于二次处理）

### 引用检查

打开文档详情顶部的 **「引用检查」** 标签页（上传/重新对齐时已自动扫描，也可「↻ 重新扫描」）：

1. 顶部胶囊显示 **全部 / 缺失 / 歧义 / 正常** 数量，点击即可**按检查状态筛选**；
   右侧下拉按引用类型筛选，搜索框匹配引用原文/目标/原因。
2. 每张卡片展示来源位置（新版第 N 段 · 第X条第N款）、引用原文（在来源段落中黄色高亮）、
   引用类型与定位结果：
   - **正常（绿）**：给出唯一目标标签与目标原文；范围引用（如“前两款”）会列出多款。
   - **缺失（红）**：新版结构中找不到目标（如条号不存在、款数不足、项不存在），不虚构目标。
   - **歧义（黄）**：存在 ≥2 个候选（如新版出现两条“第十条”、同号项分属多款），
     卡片列出**全部候选原文但不自动选取**。
3. 点击 **「查看来源 / 目标原文」** 弹出对照框，左侧高亮来源引用、右侧展示唯一目标或全部候选。
4. **「⬇ 导出问题 CSV」**：默认仅导出缺失/歧义问题项（UTF-8 BOM，Excel 可直接打开），
   含来源位置、引用原文、引用类型、状态、目标/候选原文、判定说明；
   选定某状态/类型/关键字后导出则按当前筛选条件（含正常项）。

> 引用扫描只针对**新版**文本；“本条 / 本条第N款 / 本条前款 / 前款 / 上一款 / 前两款 /
> 前条 / 第N条 / 第N条第N款 / 第（N）项 …”均支持，数字兼容中文（十、二十三）与阿拉伯数字
> （含全角 １０）。条标题自指（“第十条”作为该条标题）与行首显式款/项标签不计为引用。

## 对齐算法说明（可解释、可复现）

代码见 `app/aligner.py`：

1. **段落切分** `split_paragraphs()`
   先按空行分块；块内若出现多个条款号开头行（`第X条/章/节/款/项`、`1.`、`（一）`）
   再按编号边界细分；无结构文本回退为按非空行切分。
2. **相似度** `similarity()`
   `0.4 × difflib 原文比率 + 0.6 × 去除标点/空白/数字后比率`，对中文标点与排版差异更稳健。
3. **第一遍锚点（weighted LCS）**
   在字符集合 Jaccard 预筛后，对相似度 ≥ 0.88 的候选对做带权最长公共子序列，
   求出总相似度最大且**保持段落顺序**的高置信锚点匹配。
4. **区间对齐（Needleman–Wunsch）**
   锚点之间的未匹配区间做序列对齐（gap −0.6，配对收益由相似度映射到 −1~1）。
5. **合并/拆分识别**
   以配对列为起点贪心吸收相邻的旧段/新段游程：仅当整组相似度**上升且高于阈值 0.45**
   时判为「合并（多旧→一新）」或「拆分（一旧→多新）」；同一段落被竞争时整组相似度高者胜出。
6. **其余**：无对应旧段 → 新增；无对应新段 → 删除；1:1 且相似度 ≥ 0.88 → 未变更；
   ≥ 0.30 → 改写；手动建立的多对多 → 多段改写。
7. **置信度**：由相似度与变更类型映射（未变更 0.99~1.0、改写 0.5~0.92、
   拆分/合并 0.55~0.9、新增/删除 0.75）。
8. 每条记录同时保存 `difflib` 字符级 opcodes 与中文解释，前端做逐字 diff 高亮。

> 这是基于字符串相似度的确定性算法，不依赖任何模型；所有阈值集中在
> `app/aligner.py` 顶部常量，便于按实际语料调参。

## 引用检查算法说明（`app/citations.py`）

1. **数字解析** `parse_num()`：中文数字（十、二十三、一百零五，“两”=2）与阿拉伯数字
   （含全角 １０）统一转 int；`int_to_cn()` 负责目标标签回写。
2. **结构建立** `build_structure()`：按行解析新版段落，`第X条` 开头为条标题
   （标题引导句计为第一款），其后普通行/无标题续段依次为后续款；
   行首显式“第N款”按其编号建款；`（一）`/`1.` 行归属上一款的“项”。
   同一条号出现多个**条标题**时记录为重号（用于歧义判定）。
3. **引用切分** `extract_mentions()`：单条有序正则交替匹配绝对指代
   （`第X条`、`第X条第N款[第（N）项]`）与相对指代（`本条`、`本条第N款`、
   `本条前款`、`前款/上一款/前两款`、`前条`、裸`第N款/第（N）项`），
   相邻 token 组合成完整引用链；条标题自指与行首款/项标签剔除，
   “本条例”不会被误当作“本条”。
4. **定位** `resolve()`：按结构把引用解析到目标——
   - 条：按条标题查；0 个→**缺失**，>1 个→**歧义**（列出全部重号标题段）；
   - 款/项：先定条再定款/项；款数不足、项下无同号项→**缺失**；同号项分属多款→**歧义**；
   - 相对指代：`本条`取来源所在条；`前条`取来源条号−1；`前款/上一款`取同条上一款，
     `前两款`取同条前两款（范围引用，合法地含多个目标）；来源不在条/款结构内→**缺失**。
5. **不静默选取**：只有恰好命中唯一目标才记 `ok`；`missing`/`ambiguous` 的 `targets`
   必为空，歧义时候选完整保存在 `candidates`，交由人工确认。

## 数据模型（SQLite）

| 表 | 说明 |
|---|---|
| `documents` | 审阅任务：标题、旧版/新版全文、创建/对齐时间 |
| `paragraphs` | 切分后的段落（`side` = old/new，`idx` 为 0 基序号） |
| `alignments` | 对齐候选与审阅结果：段落序号集合、变更类型、置信度、相似度、两版组文本、字符级 diff、判定依据、是否人工、审阅决定/备注/时间 |
| `citation_checks` | 每个文档一条引用检查汇总：引用总数、正常/缺失/歧义计数、扫描时间 |
| `citation_issues` | 每条引用一行：来源段落与字符偏移、引用原文、引用类型、解析出的条/款/项号、相对指代种类、检查状态、唯一目标（`targets_json`）或全部候选（`candidates_json`）、目标标签/原文、来源位置、判定说明 |

## 已知边界

- 段落切分依赖空行或条款编号排版；极端无结构文本会按行切分。
- 算法以「保序的 1:1 主体 + 局部多对一/一对多」为模型；大范围交叉重写可能被保守地
  判为多条改写/新增/删除，审阅者可通过手动映射修正为「多段改写」。
- 引用检查只扫描**新版**文本，不跨旧版/新版解析（如“见原第X条”不在范围）。
- 相对指代基于段落排版推断条/款归属：同一篇文本建议款与款之间空行分隔，或使用行首
  显式“第N款”标签；挤在同一段落标题行后的“前款”可能无法定位，此时按**缺失**提示而非猜测。
- “第X条之一/之二”这类条号、章/节层级引用暂不解析；无法解析的编号会保守标为缺失。
